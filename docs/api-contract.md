# API Career Quest

Контракт текущего приложения: `server.js`, встроенный HTTP-сервер Node.js. Интерфейс в `public/` использует эти же маршруты. Рекомендации рассчитываются локально в `lib/domain.js` и `lib/intelligence.js`; внешних AI API и ключей провайдеров нет.

## Соединение и доступ

По умолчанию сервер доступен по `http://127.0.0.1:3000`. Принимаются только локальные Host `127.0.0.1` и `localhost`; POST с Origin должен приходить с того же адреса. Каждый POST, включая выход и сброс, требует `Content-Type: application/json` и JSON-объект. Максимальный размер тела — 8 МБ.

Вход создаёт cookie `cq_session` с `HttpOnly`, `SameSite=Strict` и сроком 8 часов. Сессии хранятся в памяти и исчезают при перезапуске. Все API, кроме входа, требуют сессию. Сотрудник видит только свой профиль; HR видит весь загруженный набор и управляет импортом и доступом.

## Маршруты

Все успешные ответы имеют HTTP 200.

| Метод и путь | Тело запроса | Ответ | Доступ |
| --- | --- | --- | --- |
| `POST /api/login` | `{ "login": "...", "password": "..." }` | `{ "role": "hr" }` или `{ "role": "employee" }`, cookie сессии | Без сессии |
| `POST /api/logout` | `{}` | `{ "ok": true }`, удаление cookie | Авторизованный |
| `GET /api/state` | — | Каталоги, профили с рекомендациями; для HR также агрегаты | Авторизованный |
| `POST /api/complete` | `{ "employee_id": "...", "activity_id": "..." }` | `{ "changes": [...] }` | Владелец профиля или HR |
| `POST /api/plan` | `{ "employee_id": "...", "source": "catalog", "task_id": "..." }`; `task_id: null` убирает выбор | `{ "ok": true }` | Владелец профиля или HR |
| `POST /api/access` | `{ "employee_id": "..." }` | `{ "login": "...", "password": "..." }` | HR |
| `POST /api/import` | Один из форматов ниже | `{ "imported": 3, "warnings": 0 }` — число сотрудников после импорта и число предупреждений | HR |
| `POST /api/reset` | `{}` | `{ "ok": true }` | HR |

`/api/access` генерирует новый код сотрудника, заменяет прежний и отзывает его действующие сессии. Полученный код передаётся сотруднику лично; примеры документов не содержат рабочих кодов.

Прежний маршрут `POST /api/practice/complete` выведен из использования и возвращает 410 после проверок доступа. Новые отметки шаблонной практики не создаются.

## Состояние и рекомендации

`GET /api/state` возвращает `role` (`hr` или `employee`), `demo` (boolean), `model` (строка), а также массивы `skills`, `grades`, `activities`, `employees`. Для нормализованного стартового набора также есть `as_of: "2026-10-01"` (строка даты); во встроенном демо это поле отсутствует.

Каждый элемент `employees` содержит профиль, актуальные `skills` (объект «идентификатор навыка → целый уровень 0–5»), историю `history` (массив записей) и вычисленные поля:

- `progression`: актуальный маршрут развития, описанный ниже. Интерфейс использует его активную цель и рекомендации.
- `next_grade`: исходный целевой профиль роли/грейда либо `null`. Поле сохранено для совместимости; это может быть явно заданная карьерная цель.
- `target_source`: `career_goal`, `next_grade` или `not_set`.
- `gaps`: массив объектов с полями `skill` и `name` (строки), `current`, `required`, `gap` (целые числа), `critical` (boolean).
- `readiness`: округлённое покрытие требований — целое число от 0 до 100 либо `null`.
- `recommendations`: прежний массив до трёх полезных допустимых активностей для исходной цели. Для активного маршрута используются `progression.recommendations`.
- `development`: прежнее представление дальнейших целей, сохранённое для совместимости. Поля: `stage` (`in_progress`, `almost_complete`, `completed`, `no_target`), `threshold: 80`, `current_readiness` (процент до округления либо null), `goals`, `completed_goals`, `message`. Новый интерфейс использует `progression`, который переключает активную цель после достижения требований.

Каждый элемент `development.goals` содержит `id`, `type` (`grade` или `skill`),
`name`, `label`, `target`, `gaps`, `readiness`, `reason`, до трёх `recommendations` и полный список `available_activities` для самостоятельного выбора.
Рекомендации имеют существующий формат и добавляют `goal_id`. Их активности
завершаются тем же `POST /api/complete`; отдельного сохранения целей не требуется:
план пересчитывается из навыков и истории.

- `available_activities`: полезные допустимые активности для выбора шага без повторов `activity.id`; тот же формат, что у рекомендаций. Активности дальнейших целей содержат `goal_id` и `goal_label`.
- `selected_task`: сохранённый выбор `{ employee_id, source, task_id }` либо `null`. Неактуальный или выполненный выбор не отображается.

`progression` содержит:

- `stage`: `in_progress` — активная цель в работе, `almost_complete` — достигнут порог предварительного показа дальнейшей цели, `no_steps` — нет подходящего шага в каталоге, `complete` — доступные цели достигнуты;
- `active_goal`: первая ещё не достигнутая цель развития либо `null`;
- `upcoming_goals`: предварительные следующие цели при покрытии не менее 80% требований активной цели; до порога массив пуст;
- `completed_goals`: краткие описания целей, требования которых уже выполнены;
- `recommendations`: до трёх подходящих активностей для активной цели;
- `message`: объяснение текущего состояния маршрута;
- `threshold: 80`: точный порог покрытия до округления для предварительного показа дальнейших целей.

Объекты `active_goal` и `upcoming_goals` содержат `id`, `type`, `name`, `label`,
`target`, `gaps`, `readiness`, `recommendations`, `available_activities`;
цели по навыкам дополнительно содержат `reason`. После достижения требований активная цель автоматически
переключается на следующий ещё не достигнутый грейд в цепочке, а затем — на
доступные цели по навыкам. При отсутствии полезных активностей система сообщает
о необходимости согласовать шаг с HR и дополнить каталог. Фактический `grade`
и исходная `career_goal` при этом не меняются.

Покрытие: `100 * sum(min(current, required)) / sum(required)` по навыкам целевого профиля. Если знаменатель равен нулю, в том числе при отсутствии цели, API возвращает `null`: вычислимого процента нет. Покрытие не гарантирует повышения.

В рекомендации находятся `activity` (объект мероприятия), `effects` и `reasons` (массивы), `impact` и `score` (числа), `behavior` (объект), `explanation` (строка). Каждый элемент `effects` содержит `skill` (строка), `before`, `after`, `gain`, `max_level` (целые числа); элементы `reasons` добавляют `name`, `required`, `critical`, `covered`. `behavior` содержит `probability` (число от 0 до 1), `successes`, `failures`, `observations` (целые количества) и `explanation` (строка).

Оценка ранжирования: `impact * (0.25 + 0.75 * probability)`, где критичные дефициты имеют двойной вес. Вероятность основана на сглаженной статистике завершений и личной истории. Это статистическая модель, не LLM. Отбор учитывает текущую роль, грейд, входные требования, расписание, обязательность и историю. Активности в процессе не предлагаются как новые.

Только HR получает `warnings` — число предупреждений импорта — и `hr`:

- `deficits`: навыки с дефицитами и число сотрудников с каждым дефицитом;
- `participation`: количества записей по активностям и статусам;
- `no_step`: сотрудники без рекомендации и причины;
- `inactive`: сотрудники без записей истории за последние 90 дней относительно даты расчёта.

## Завершение и прогресс

`POST /api/complete` меняет навыки и добавляет завершение в историю. В `changes` возвращается массив объектов с полями `skill`, `before`, `after`, `gain`, `max_level`, того же формата, что `effects`. Клиент затем запрашивает `/api/state`, чтобы обновить активную цель, следующие шаги, предварительный план дальнейшего развития и HR-срез. При достижении цели её место занимает следующая, без отдельного запроса на переключение.

Новый уровень: `max(current, min(current + gain, max_level))`. Завершение датируется `as_of`, а при его отсутствии — текущей датой UTC. Повторное завершение неповторяемой активности и завершение активности `in_progress` возвращают 400 без нового начисления. Для регулярного клуба повторное начисление в один день запрещено. API не содержит отдельного маршрута записи на событие или завершения по `record_id`.

## Выбор следующего шага

Выбор шага не начисляет навыки. Сервер проверяет доступность, пользу для цели и права на профиль; выбор сохраняется после перезапуска. Допускается только источник `catalog`. Входные требования курса нельзя обойти выбором из полного списка.

При нехватке активности каталог не дополняется вымышленными заданиями. API возвращает доступные варианты либо пустой список с объяснением в `progression.message`.

Сохранённые в старых версиях записи шаблонной практики не отображаются и не учитываются в навыках, покрытии целей, истории активностей или статистике HR. Выбор такой практики больше не принимается, а её маршрут завершения возвращает 410.

Полный импорт и сброс очищают выбор и прежние записи практики. Частичный импорт очищает их только для заменяемых профилей, сохраняя прогресс остальных. Эти записи не принимаются как доверенные данные из загружаемых файлов.

## Импорт и сброс

Импорт выполняется одним JSON-запросом, без multipart и отдельного шага подтверждения на сервере. Интерфейс читает выбранные файлы и собирает тело запроса.

1. Полный стартовый набор: `skills`, `events`, `employees`, `history`. `skills` содержит каталог и `role_profiles`; `events` и `employees` допускают массивы или оболочки с одноимённым полем. `history` — текст CSV либо массив записей. Полный импорт заменяет текущий набор.
2. Профили жюри: `{ "mode": "profiles", "employees": [...], "history": "...CSV..." }`. Требует ранее загруженного стартового набора. Добавляет новые профили, заменяет совпадающие профили и их историю; прогресс остальных сотрудников сохраняется. История должна относиться к импортируемым профилям.
3. Формат встроенного демо: объект `skills`, `grades`, `activities`, `employees`, как в `demo.json`.

CSV требует столбцы `record_id`, `employee_id`, `event_id`, `date`, `status`, `completion_pct`. Веб-импорт не читает XLSX напрямую: историю сначала преобразуют в CSV. Нормализация проверяет ссылки, даты, диапазоны навыков и карьерные цели. Завершения после `last_review_date` пересчитывают навыки; повторные завершения сохраняются в истории без повторного начисления согласно правилам активности. Возможность построить профиль проверяется до сохранения импорта.

Любой успешный импорт снимает признак демо и отзывает все коды и сессии сотрудников. HR остаётся авторизованным. `/api/reset` восстанавливает настроенный исходный набор, а если источник не задан — встроенное демо; коды сотрудников также отзываются.

## Ошибки и хранение

Форма ошибки: `{ "error": "Понятное сообщение" }`. Используются 400 для неверных данных или недопустимого действия, 401 для отсутствующей/просроченной сессии, 403 для запрещённого доступа или источника, 404 для неизвестного маршрута после проверки доступа, 410 для выведенного из использования завершения практики, 415 для неверного Content-Type и 429 для превышения лимита входов. Лимит входов — 20 попыток за минуту на адрес.

Состояние и учётные записи сохраняются локально; каталог хранения задаётся `CAREER_QUEST_STORAGE`, исходный набор — `CAREER_QUEST_DATASET`. При наличии сохранённого состояния запуск восстанавливает его; новый источник применяется после сброса либо в отдельном каталоге хранения. Приватные наборы, состояние и коды доступа не включаются в репозиторий. Запуск и проверка: `npm start`, `npm test`.
