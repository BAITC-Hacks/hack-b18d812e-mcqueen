# Самостоятельная проверка Career Quest для жюри

Решение сдаётся через репозиторий команды. Приложение запускается локально на
компьютере проверяющего; публичного сайта нет.

## Запуск

1. Скачайте свежую копию репозитория. Требуется Node.js 20+.
2. В Windows откройте `start.cmd`, либо выполните `node server.js` в папке проекта.
3. Откройте `http://localhost:3000`. Если задан `PORT`, используйте его значение.
4. В терминале показаны логин `hr` и код доступа. Не публикуйте код.
5. Без стартового кита загрузится `demo.json` с тремя вымышленными сотрудниками.
   Внешние API и установка пакетов не нужны.

Адрес localhost относится к тому компьютеру, на котором открыт браузер.
Для повторной проверки с нуля можно указать новую папку `CAREER_QUEST_STORAGE`.
Импорт кита описан в README; локальные данные и файлы доступа в Git не включены.

## Что проверить

- У «Демо: Алия» начальная цель развития — Middle, покрытие требований — 38%.
- На вкладке «Рекомендации» показаны шаги к активной цели. Обоснование
  «Практикума Python»: текущий уровень 1, требуется 3, прирост +2.
- На вкладке «Все шаги» добавьте практикум в план: выбор не меняет навыки.
  Нажатие «Завершить шаг» применяет прирост и даёт покрытие 63%.
- После «SQL: от запроса к решению» покрытие — 88%. В блоке «Следующая цель уже
  рядом» появляется Senior; Middle пока остаётся активной целью.
- После «Демо для команды» требования Middle выполнены. В основном маршруте
  активной целью становится Senior с новым процентом и шагом «Проект с наставником».
  Middle указан среди выполненных требований; фактический грейд остаётся Junior.
- Завершите «Проект с наставником»: навыки и история обновятся. В небольшом
  демокаталоге больше нет подходящего шага для оставшихся требований Senior,
  поэтому система предложит согласовать развитие с HR и дополнить каталог.
- Перезапустите приложение и войдите снова: навыки, история и актуальная цель
  сохраняются. Выполненные неповторяемые активности снова не предлагаются.
- HR видит дефициты компетенций, отсутствие шагов и участие в программах.
- HR может выдать код сотруднику; после входа с ним доступен только свой профиль.

## AI-слой и ограничения

Рекомендации учитывают активную цель развития, разрывы навыков, доступность активностей
и историю. Локальная байесовская модель оценивает вероятность завершения;
это прогноз, а не гарантия повышения. Обоснования связаны с факторами расчёта.
LLM и внешние AI API не подключены. Шаги берутся из каталога: после завершения
система пересчитывает прогресс и выбирает следующие подходящие активности.
Если каталог не покрывает дефицит, это явно указано. Завершение курса моделируется
кнопкой; подтверждение наставником пока не реализовано.

Для проверки качества разберите рекомендации 3–5 профилей из разрешённого набора:
цель → дефицит → доступность → ожидаемый прирост → обоснование.
Автоматические проверки запускаются командой `node --test`; качество на закрытых
профилях жюри ещё предстоит оценить.
