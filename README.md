# Career Quest

Локальный MVP платформы развития сотрудников для хакатона McQueen: до трёх
объяснимых рекомендаций по требованиям следующего грейда, разрывам навыков
и истории участия. Есть маршрут сотрудника, HR-обзор и импорт JSON.

## Запуск одной командой

Нужен **Node.js 20+**. Устанавливать пакеты не требуется.

```sh
npm start
```

Откройте http://127.0.0.1:3000. Остановка: Ctrl+C.
Альтернатива: `node server.js`. Порт задаётся переменной окружения `PORT`.

## Быстрая проверка

1. Выберите «Демо: Алия»: видны требования Middle и три рекомендации.
2. Завершите «Практикум Python»: Python вырастет с 1 до 3, появится история,
   рекомендации пересчитаются. Завершённая активность больше не предлагается.
3. Откройте HR-обзор: проверьте покрытие требований и разрывы навыков.
4. Импортируйте JSON в формате `demo.json` через HR-экран.
5. Перезапустите сервер: завершения и импорт сохраняются.

Все профили и активности в `demo.json` **синтетические**. Реального датасета нет.

## Алгоритм

- Следующий грейд определяется полем `next_grade` текущего грейда.
- Разрыв: `max(0, required - current)`. Отсутствующий навык считается нулевым.
- Новый уровень: `max(current, min(current + gain, max_level))`.
  Активность никогда не понижает уже достигнутый уровень.
- Исключаются завершённые активности и активности с невыполненными `prerequisites`.
- Оценка — сумма `min(разрыв, фактический прирост)` по целевым навыкам.
  Выдаются до трёх активностей с положительной оценкой; при равенстве — по `id`.
- Объяснение показывает навык, текущий и прогнозируемый уровни, цель,
  закрываемую часть разрыва и предел активности.
- Рекомендации оцениваются независимо, это не оптимизация совместного плана.
  После каждого завершения список пересчитывается.
- Импортированная история не начисляет навыки повторно: `skills` задаёт актуальное
  состояние профиля. Повторное завершение одной активности запрещено.
- Покрытие — сумма достигнутых целевых уровней, ограниченных требованиями,
  делённая на сумму требований. Грейд автоматически не меняется.
  Для последнего грейда рекомендации не выдаются.

## Импорт проверочных профилей

JSON до 2 МБ **заменяет весь текущий набор**, включая каталог и историю,
после подтверждения в интерфейсе. Невалидный набор не сохраняется.
«Вернуть демо» также заменяет текущий набор после подтверждения.
Шаблон — `demo.json`:

| Поле | Формат |
| --- | --- |
| `skills` | Массив `{id, name}` |
| `grades` | Массив `{id, name, next_grade, requirements: {skill_id: level}}` |
| `activities` | Массив `{id, name, description?, prerequisites?, effects}` |
| `effects` внутри активности | Массив `{skill: skill_id, gain, max_level}` |
| `employees` | Массив `{id, name, grade, skills: {skill_id: level}, history}` |
| `history` внутри профиля | Массив `{activity_id, completed_at}`; дата ISO 8601 |

`next_grade` — существующий id или `null`; циклы запрещены.
`prerequisites` — необязательный объект `{skill_id: минимальный_уровень}`.
Уровни — целые 0–100; `gain` и `max_level` — 1–100.
Id — 1–80 латинских букв, цифр, `_` или `-`, уникальные внутри массива.
Ссылки проверяются. Навыки в effects и активности в истории не повторяются.

Формат датасета хакатона пока неизвестен. Для CSV/XLSX или другой схемы нужен
адаптер: текущий импорт поддерживает только описанную JSON-схему.

## Данные и ограничения MVP

Сервер слушает только `127.0.0.1`. Внешних API, CDN и аналитики нет.
После изменения данные сохраняются в `data/state.json` с заменой через временный файл.
Каталог `data/` исключён из Git. Повреждённое сохранение вызывает ошибку запуска,
а не молча заменяется демоданными. Запускайте один сервер на каталог данных.

**Датасет нельзя выносить за пределы хакатона.** Не коммитьте реальные профили
и не загружайте их во внешние сервисы; входные файлы храните внутри `data/`.
Текущая рабочая папка расположена в OneDrive: перед работой с реальными данными
перенесите приложение в разрешённую правилами хакатона папку без облачной синхронизации.

Это локальный MVP без авторизации, разделения прав, подтверждения прохождения
наставником и автоматического повышения. HR-переключатель не является контролем доступа.

## Проверки и структура

```sh
npm test
```

Тесты покрывают рекомендации, gain/max_level, запрет повторного начисления,
входные требования, готовые профили, последний грейд и валидацию импорта.

- `server.js` — HTTP API, статические файлы, сохранение состояния.
- `lib/domain.js` — валидация и бизнес-логика.
- `public/` — интерфейс HTML/CSS/JavaScript без сборки.
- `demo.json` — синтетический пример импортируемого набора.
- `tests/domain.test.js` — тесты на встроенном Node.js test runner.

API: `GET /api/state`, `POST /api/complete` (`employee_id`, `activity_id`),
`POST /api/import` (полный набор), `POST /api/reset` (`{}`). POST принимает JSON.
