# Career Quest

Локальная платформа развития сотрудников для кейса 1 HackAlem AI. Сотрудник видит
профиль, требования следующего грейда и до трёх объяснимых рекомендаций. HR видит
дефициты навыков, отсутствие следующих шагов и участие в программах.

## Запуск

Требуется Node.js 20+. Зависимости устанавливать не нужно. Из папки репозитория:

```powershell
npm.cmd start
```

Откройте http://127.0.0.1:3000. На других оболочках работает `npm start`,
альтернатива — `node server.js`. Остановка — Ctrl+C. После обновления кода
перезапустите сервер. `PORT` меняет порт. Приложение слушает только 127.0.0.1.

Без стартового кита запускается синтетический мини-пример `demo.json`.
Для подключения кита при первом запуске укажите папку:

```powershell
$env:CAREER_QUEST_DATASET = 'C:\путь\career_quest_dataset'
npm.cmd start
```

В этой папке нужны `skills.json`, `events.json`, `employees.json` и
`activity_history.csv`. Локальное подключение также можно задать в игнорируемом
`data/source.json`: объект с полем `directory`. Уже сохранённое состояние имеет
приоритет над источником; заменить его можно через полный импорт или восстановление
исходного набора в HR-экране. Эти действия требуют подтверждения и сбрасывают прогресс.

## Вход и права

При первом запуске создаётся HR-аккаунт с логином `hr` и случайным кодом.
Путь к локальному файлу **hr-access.txt** выводится в терминале. Откройте этот файл
и введите код в форме входа; не публикуйте его и не отправляйте вместе с проектом.

HR выбирает сотрудника и нажимает «Выдать новый код сотруднику». Логин и код
показываются один раз в интерфейсе для личной передачи. Повторная выдача отзывает
старый код и сессии этого сотрудника. Сотрудник получает только собственный профиль,
историю и рекомендации; импорт, сброс, сводки и выдача кодов защищены серверной
проверкой роли. Выбор employee_id в запросе не даёт доступ к чужому профилю.

Коды хранятся как scrypt-хеши с солью. Сессии — HttpOnly / SameSite=Strict cookies
на 8 часов, в памяти процесса; перезапуск требует повторного входа. Ограничение
попыток входа — 20 в минуту с адреса. После импорта и сброса все коды и сессии
сотрудников отзываются, HR выдаёт новые. HR-код не меняется.

## Сценарий для жюри

1. Войти как HR. Открыть профиль: роль, стаж, грейд, все навыки и требования
   следующего грейда; критичные навыки помечены звёздочкой.
2. Проверить 1–3 рекомендации: целевой грейд, разрыв навыка, ожидаемый прирост,
   история завершений/пропусков/отказов и модельная вероятность завершения.
3. Отметить рекомендуемую активность выполненной. Навык изменится согласно
   gain/max_level, появится запись истории, маршрут и HR-сводки пересчитаются.
4. В HR-экране проверить частые разрывы, сотрудников без следующего шага,
   отсутствие участия за 90 дней и количество записей каждого статуса по событию.
5. Импортировать проверочные employees.json и activity_history.csv в режиме
   «Добавить / заменить профили и их историю». Существующие другие сотрудники
   сохраняют свой прогресс. Проверить рекомендации для загруженных профилей.
6. Выдать код сотруднику, выйти из HR и войти с этим кодом. Доступен только свой
   профиль, HR-экран отсутствует; сервер также отклоняет чужие операции.
7. Перезапустить приложение и повторно войти: данные и прогресс сохраняются.

## Данные и импорт

Адаптер читает исходную схему кита: employees.employees, events.events,
skills.skills и skills.role_profiles, журнал CSV. Массив сотрудников допустим
как отдельный JSON-массив. Уровни навыков — 0–5. Дата среза — **2026-10-01**,
как указано в README кита; эта дата используется для расписания и HR-аналитики.

В HR-экране выберите файлы с исходными именами (до 8 МБ суммарно):

- Частичный импорт: employees.json + activity_history.csv. Добавляет сотрудников;
  совпадающий employee_id заменяет профиль и всю его историю. История должна
  относиться только к загружаемым сотрудникам, но может быть пустой с заголовком CSV.
- Полный импорт: эти два файла + skills.json + events.json. Заменяет весь набор.

Проверяются id и ссылки, роль/грейд, шкала навыков, эффекты, статусы и даты.
Ошибка не заменяет текущее состояние. В CSV поддержаны ISO-даты и дд/мм/гггг,
кавычки, запятые внутри кавычек и CRLF.

Уровни профиля отражают last_review_date: завершения после этой даты применяются
в хронологическом порядке. История ранее или в день оценки не начисляется снова.
Повторный импорт того же профиля пересчитывается от исходной оценки, без накопления.
В исходном наборе обнаружены повторные completed для неповторяемых мероприятий:
они сохраняются для просмотра, но повторный прирост блокируется и учитывается
в предупреждениях HR. EV_036 является повторяемым; повторное начисление в один
день запрещено. Одинаковые record_id считаются ошибкой импорта.

## Рекомендации и локальная AI-модель

Используется **локальная эмпирическая Bayesian-модель завершения**, без LLM и
без внешних API. Это статистическая рекомендательная система, не генеративный чат.
AI-агент Codex использовался также при разработке.

1. Для роли сотрудника выбирается следующий грейд Junior → Middle → Senior → Lead.
2. Исключаются обязательные события, неподходящая аудитория, невыполненные
   prerequisites, отсутствующие будущие сессии (кроме self_paced) и уже завершённые
   неповторяемые активности. После завершения EV_036 новая рекомендация возможна
   со следующего дня при наличии доступной сессии.
3. Разрыв = max(0, требование − уровень). Прирост = max(0, min(уровень + gain,
   max_level) − уровень). Навык никогда не понижается.
4. Полезность = сумма закрываемых уровней разрывов, с двойным весом critical_skills.
5. Модель обучается на completed и no_show/declined/dropped добровольных событий,
   группируя наблюдения по типу и формату. in_progress/overdue не считаются исходом.
   Средняя вероятность группы сглажена Beta(1,1). Личная история исключается
   из групповой оценки, затем добавляется отдельно с весом априорной оценки 2:
   `p = (2 * prior + личные завершения) / (2 + личные завершения + личные неуспехи)`.
6. Оценка = полезность × (0.25 + 0.75 × p). При равенстве — порядок id.
   Выдаётся до трёх положительных вариантов. После завершения модель обновляется.

Минимальный вес 0.25 сохраняет возможность развития даже после пропусков. Личная
история не превращается в запрет на обучение. Объяснение перечисляет реальные
факторы расчёта и не генерирует неподтверждённых фактов. Для сотрудника без истории
показывается, что использована сглаженная оценка. Вероятности не калиброваны на
отдельной тестовой выборке; это прогноз, а не гарантия завершения.

## HR и приватность

HR получает частоту дефицитов по навыкам; список профилей без рекомендаций
с причинами (последний грейд, требования выполнены, нет подходящего события);
список без записей участия за 90 дней; статусы по активностям. Это записи участия,
а не уникальные люди: повторные посещения клуба учитываются отдельно. Публичных
рейтингов сотрудников и баллов за обязательные процессы нет. Другим сотрудникам
профили и вовлечённость не выдаются. Повышение грейда не происходит автоматически.

Датасет хакатона **не включён в Git** и не отправляется во внешние сервисы.
Имена и записи в demo.json и тестах придуманы для этого приложения.
Состояние и доступы по умолчанию находятся вне OneDrive, в системной временной
папке `career-quest-<идентификатор проекта>`; точный путь печатается при старте.
Эта папка переживает перезапуск, но ОС может её очистить. Для долговременного
хранения задайте `CAREER_QUEST_STORAGE` на разрешённую локальную папку без
облачной синхронизации. В data/ репозитория хранятся только игнорируемая конфигурация
подключения и локальные вспомогательные файлы. Старое data/state.json предыдущей
версии автоматически не мигрируется и не удаляется.

Источник кита может находиться в OneDrive: приложение читает его локально, но
не управляет синхронизацией исходной папки. Соблюдение запрета на вынос данных
требует хранить сам кит в разрешённом организаторами месте без синхронизации.

## Архитектура и проверка

Node.js HTTP + HTML/CSS/JavaScript, без сторонних зависимостей и сборки.

- server.js — локальный сервер, вход, сессии, права, хранение и API.
- lib/dataset.js — адаптер исходных JSON/CSV и частичный импорт.
- lib/domain.js — требования, эффекты активностей, рекомендации, HR-сводки.
- lib/intelligence.js — обучение и предсказание локальной Bayesian-модели.
- public/ — адаптивный интерфейс сотрудника и HR.
- tests/ — бизнес-логика, импорт и HTTP-проверки доступа на независимых примерах.

```powershell
npm.cmd test
```

Тесты проверяют сложный профиль с низким навыком и повторными пропусками,
критичные требования грейда, ограничения мероприятий, доначисление после оценки,
идемпотентность импорта, повторы, права сотрудника/HR и сохранение при перезапуске.

API: POST /api/login, /api/logout, /api/complete, /api/access (HR),
/api/import (HR), /api/reset (HR); GET /api/state (только разрешённые профили).
POST принимает JSON, сессия передаётся cookie. Изменение из другого Origin запрещено.

## Ограничения и сдача

Локальный MVP: нет SSO, производственного HTTPS, журнала аудита и подтверждения
прохождения наставником. Кнопка завершения моделирует прохождение; даты фиксированы
срезом набора, календарь сессий не исполняется как реальная система регистрации.
Интерфейс русский, названия из кита остаются на языке источника. career_goal
сохраняется, но текущая траектория ведёт к следующему грейду текущей роли.
Рекомендации — отдельные варианты, без оптимизации совместного учебного плана.
Использование именно LLM не реализовано; качество локального статистического
подхода предстоит оценить на закрытых профилях жюри. Запускайте один сервер на
каталог состояния; шифрования файлов на диске нет. Владельцы ОС имеют доступ
к локальным файлам, серверное разграничение не защищает от владельца компьютера.

Публичной deployed-версии нет. Порядок сдачи — в HACKATHON.md.
